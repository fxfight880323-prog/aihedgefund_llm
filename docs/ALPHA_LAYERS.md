# AI Fund Framework — 三层 Alpha 目标结构

> 更新：2026-08-20
> 框架的三个目标层，把「超额收益从哪来」拆成三个可独立记账、鉴别、迭代的层面：
> **数据/信息源层 → Alpha/方法论层 → 数量信号层**。
> 任何一次回测改进，必须归因到恰好一层；每层有独立的 benchmark 与迭代协议。

---

## 一、总览

```
┌────────────────────────────────────────────────────────────────┐
│  策略总收益 = 基准收益 + 数据α + 方法论α + 数量信号α           │
│              (基准: 等权万得全A PIT 池)                        │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  L1  数据层 / 信息源层    Data Edge                             │
│      「接入什么数据，决定了 alpha 的天花板」                    │
│      记录：数据源 / 信息源 / MCP 接入 → 鉴别 → 实测超额         │
│      benchmark：同一方法论下，基线数据源 vs 新数据源             │
│                                                                │
│  L2  Alpha 层 / 方法论层   Methodology Edge                    │
│      「怎么决策，决定了 alpha 能否被稳定提取」                  │
│      记录：方法论 → benchmark → 迭代 → 实测超额                 │
│      benchmark：F-Score 基线（已证实跑赢全A等权）               │
│                                                                │
│  L3  数量信号层  Signal Edge（A股：卖得好比买得好重要）         │
│      「什么时候买卖，决定了 alpha 的兑现率」                    │
│      记录：买入信号 / 卖出信号 / 过热 / 回撤纪律 → 实测增量     │
│      benchmark：无信号基线组合 vs 加信号组合                    │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 三条铁律

1. **每笔 alpha 只能记在一个层**——数据换来的记数据层，方法论换来的记方法论层，
   定量信号换来的记数量信号层；禁止重复记账。
2. **先对比再下结论**——任何改进必须对照等权万得全A PIT 池（EW-全A），
   高收益可能只是池子 beta 或幸存者偏差。
3. **无效实验也要记账**——否决项（IRR 门控、BSADF 叠加、ROA 加权…）与有效项同等重要，
   防止同一坑踩两次。

## 二、L1 数据层 / 信息源层（Data Edge）

### 使命

- 持续接入**能带来超额收益**的数据源与信息源：券商 MCP、交易所 PIT 数据、
  一致预期、资金流、龙虎榜、宏观、另类数据等。
- 在本层做**鉴别分析**：一个数据源是否值得接入，取决于它能否让
  **同一方法论**在回测中产生正的超额增量——而不是它本身多"高大上"。

### 记录载体

- 账本：`alpha_ledger/ledger.json` → `layers.data.entries[]`
- 代码：`src/data/*.py`（DataClient 协议）+ MCP 接入配置
- 每个数据源一条记录：来源 / 覆盖范围 / PIT 能力 / 接入日期 / 实测超额 / 鉴别结论

### 鉴别协议（数据源 A/B 测试）

```
新数据源 → 用「标准方法论」（默认 C-Score 矩阵）跑同一池子同一区间
        → 对比基线数据源（财报/行情）
        → 超额增量 > 0 且回撤未显著恶化  → 记为 VERIFIED，入账数据层
        → 超额增量 ≤ 0                   → 记为 REJECTED，入账（防止重复接入）
```

### 本层已记账（实测）

| 数据源 | 接入方式 | 实测（同一方法论下增量） | 结论 |
|--------|----------|--------------------------|------|
| juzi con_forecast_stk 一致预期 PIT | juzi-mcp `factor_get_consensus_forecast` | C-Score +30.7% / 超额 +26.2pp（vs F-Score 财报基线 +12.6%） | ✅ VERIFIED 数据层核心资产 |
| 万得全A 881001.WI PIT 成分 | juzi-mcp `factor_get_universe_members` | 消除幸存者偏差 ~53pp（龙头池 +455% vs 全A等权 +52.9%） | ✅ VERIFIED 基准池 |
| 腾讯月K 行情 | 线程池批量抓取 | 全市场 5500+ 只价格，回测必需 | ✅ VERIFIED 基础设施 |
| 券商/新 MCP | 待接入 | — | ⏳ 待鉴别 |

### 迭代协议

- 新数据源一律先走 A/B 鉴别，**通过才升级为生产数据**。
- 每半年回顾：已入账数据源是否仍产生增量；若衰减（如一致预期拥挤化），标记 DEGRADING。

## 三、L2 Alpha 层 / 方法论层（Methodology Edge）

### 使命

- 记录**能带来超额收益的方法论**，并为其设置 benchmark。
- 方法论 = 决策框架/打分规则/纪律体系（不是数据，也不是单笔买卖信号）。
- 持续迭代：每个方法论维护版本线，新变体必须跑赢自身 benchmark 才能晋级。

### Benchmark 设置（本层核心）

```
方法论 benchmark 三层对照：
  ① 池子基准    EW-全A PIT 等权           （绝对底线，跑不赢 = 无 alpha）
  ② 方法论基线  F-Score 预期差 (+12.6%/超额+8.1pp)  （已证实的方法论门槛）
  ③ 自身 v0     该方法论的第一个版本       （迭代是否进步）
晋级规则：新变体 超额 > ② 且 回撤不显著恶化 → 晋级为方法论新版本；
         否则回滚并记账教训。
```

### 本层已记账（实测）

| 方法论 | 基准对照 | 实测 | 结论 |
|--------|----------|------|------|
| F-Score 预期差（Piotroski-So + 刘旭纪律） | EW-全A +52.9% | 5年 +12.6% / MDD -14.4% / 超额 +8.1pp | ✅ VERIFIED 方法论基线 |
| ZHF 否决制（consensus_veto 只否决不打分） | ZHF 打分制 -7.3% | ZHF-veto -2.6%（+4.7pp） | ✅ VERIFIED 「预期信息量在方向变动，非水平排序」 |
| 章宏帆框架（rotation_growth） | 龙头池等权 +455% | ZHF-cons +329.1% / MDD -27.0%（跑输池子） | ⚠️ 框架价值=纪律(MDD砍半) 非选股 |
| Growth Loop 剧本 | EW-全A | 纯增速 5年 -14.0% / MDD -56.6%（Growth Trap） | ❌ REJECTED 追高接盘循环 |
| ROA 加权 | F-Score 基线 | -3.7pp（周期股盈利峰值偏误） | ❌ REJECTED 教训 |
| IRR 门控 / BSADF 叠加 / 减速清仓 | F-Score 基线 | 无效 | ❌ REJECTED 教训 |

### 迭代协议

- 每次迭代 = 一个变体实验（variants），必须与 ①②③ 三个 benchmark 同时对比。
- 有效方法论沉淀进 `config/strategies/*.yaml`；无效的记入账本 REJECTED，不删结论。
- **卖出的方法论（估值卖出 +11pp）记入 L3**——因为它是"何时卖"的定量信号，
  不是决策框架本身。边界判定见第五节。

## 四、L3 数量信号层（Signal Edge）

### 使命（A股：卖得好比买得好重要）

- 记录**买卖时点信号**，尤其是**卖出与过热**：
  估值过热、涨幅过热、泡沫相位、回撤纪律、预期下修。
- 数量信号 = 单个可叠加的定量规则，加到任一方法论/组合之上，测量增量。

### benchmark 设置

```
数量信号 benchmark：同一方法论同一组合，无信号基线 vs 加信号
增量 = 加信号后收益差（总收益、MDD、换手三维同时看）
晋级规则：MDD 显著改善 或 收益改善且 MDD 不恶化 → VERIFIED；
         收益换取回撤（MDD 恶化）→ 明确记账为「收益换回撤，非免费午餐」
```

### 本层已记账（实测）

| 信号 | 施加对象 | 实测 | 结论 |
|------|----------|------|------|
| 估值卖出（PE 上限/高估降权） | F-Score | **+11pp**（有效改进） | ✅ VERIFIED 卖出>买入 |
| BSADF 泡沫检验（调仓月叠加） | Growth Loop | 略优于基线（泡沫期减仓） | ✅ VERIFIED（弱） |
| BSADF 逐月出场 | Growth Loop | 主升段卖飞赢家（-2.9pp） | ❌ REJECTED 月频无法区分抛物线回撤 vs 真破裂 |
| yoy_drop 下修清仓（每半年） | ZHF-veto | MDD **-66.3%**（清仓接刀→割肉换血循环） | ❌ REJECTED 超灵敏砍太狠 |
| 回撤止损 dd50%/yoy50pp（strict） | ZHF-veto | MDD -73.0%（止损太晚） | ❌ REJECTED 无甜蜜点 |
| 涨幅分解 G5（ΔPE 主导→信念×0.5） | rotation_growth | 框架内置过热降温 | ✅ VERIFIED 框架内置 |

### 过热监控清单（A股卖出候选信号，待逐一鉴别）

- [ ] 个股 1 年涨幅热度罚（Growth Loop Serenity 已内置，待独立归因）
- [ ] 换手率/成交额过热（westock data 可拉）
- [ ] 龙虎榜/北向资金异动（MX MCP 可拉）
- [ ] 一致预期上修终止（con_np_yoy 转负 → 已有 veto 使用，待独立归因）
- [ ] 技术顶背离（MACD/RSI，tech_confluence 已有，待独立归因）

## 五、归因协议：一笔改进记到哪一层？

判定顺序（自上而下，命中即止）：

```
1. 换的是「数据源/信息源」吗？          → L1 数据层
   （同一方法论、同一信号，仅数据不同 → 增量全归数据层）
2. 换的是「决策框架/打分规则/纪律体系」吗？ → L2 方法论层
   （同一数据、同一信号，决策树不同 → 增量全归方法论层）
3. 换的是「买卖时点/过热/止损信号」吗？   → L3 数量信号层
   （同一方法论、同一数据，加减信号 → 增量全归信号层）
4. 跨层组合（如 F×C 混合）→ 拆成单因子实验分别归因，交互项记「未归因」。
```

**边界案例（已按此执行）**：
- 估值卖出 → L3（卖出信号），不是方法论；
- C-Score 矩阵结构 → L2（方法论），但它证明了 L1 的数据价值，故在数据层也记一条 VERIFIED；
- 万得全A PIT 池 → L1（数据质量），同时是全框架 benchmark 的载体。

## 六、层间对比与使用方式

### 一句话总结各层现状（2026-08）

| 层 | 有效资产 | 核心教训 | 下一步 |
|----|----------|----------|--------|
| L1 数据层 | 一致预期 PIT 数据（+26.2pp） | 数据源决定 alpha 天花板 | 接入券商 MCP 走 A/B 鉴别 |
| L2 方法论层 | F-Score 基线（+8.1pp）、否决制（+4.7pp） | 框架价值在纪律非选股 | 迭代卖出方法论 |
| L3 数量信号层 | 估值卖出（+11pp） | 卖出纪律=收益换回撤非免费午餐 | 鉴别过热清单 |

### 使用方式

- 账本文件：`alpha_ledger/ledger.json`（程序读取）
- 对比报告：`python examples/alpha_ledger_report.py` → `alpha_ledger_report.html`
- 记账模块：`src/research/alpha_ledger.py`（AlphaLedger 类：add / attribute / compare / export）
- 新实验流程：跑回测 → 判定归属层 → 写入账本（有效/无效都记）→ 重生成报告

### 与现有代码的映射

```
L1 数据层   → src/data/（DataClient） + MCP 接入（juzi / mx / westock…）
L2 方法论层 → config/strategies/*.yaml + src/signals/*.py（打分/决策）
L3 数量信号层 → src/signals/bsadf.py, tech_confluence.py, hooks.py（卖出/过热）
              + src/risk/limits.py（回撤止损）
账本        → alpha_ledger/ledger.json + src/research/alpha_ledger.py
```

---

*三层结构是框架的「导航仪」：数据层决定看得多远，方法论层决定怎么走，
数量信号层决定何时停。三者分开记账，合起来才是完整的 alpha 地图。*
